# Хаб на английском с выбором языка

## Зачем

Хаб ставят себе другие люди с GitHub (README и документация уже на английском). Сейчас весь хаб говорит по-русски:
админка, служебные страницы и всё, что видит модель. Нужно, чтобы язык выбирался в настройках и по умолчанию был английский.

## Цели

- Язык — **одна настройка на весь хаб**: English или Русский. Не на пользователя и не на браузер.
- Язык меняет **всё, что видят человек и модель**:
  - админка целиком, включая подписи, подсказки и ошибки полей форм коннекторов (`configSchema` — `label`, `help`, `placeholder`, сообщения zod);
  - вход и 2FA, страница пин-кода прототипов, страницы ссылок `/f/{token}` (`simplePage`), 404/410 и прочие служебные страницы;
  - всё MCP: описания инструментов и параметров, ответы инструментов (включая ошибки `ToolError` и сообщения сервисов вроде «X не ответил за 30 с»),
    `instructions` коннекторов, тексты сервера (`lib/mcp/server.ts`, `hub_guide`, `hub_status`, стартовый текст «Свой initialize»);
  - тексты песочницы скриптов, которые видит модель (`SANDBOX_API_DOC`, ошибки запуска, `limitsLine`);
  - форматирование: даты, «5 минут назад», множественное число, размеры (`lib/format.ts`, `lib/connectors/format.ts`), `<html lang>`.
- **По умолчанию английский** для новых установок.
- **Без миграции** (решение пользователя): существующая установка после обновления тоже станет английской, язык переключают в настройках.
  В заметках к релизу и в документации — «после обновления выберите язык в Settings», плюс то же про язык озвучки Jackett.
- Переключатель **на странице «Настройки» / Settings**, менять можно в любой момент в обе стороны.
  - Админка и служебные страницы — сразу.
  - Ответы инструментов — со следующего вызова.
  - Описания инструментов и `instructions` — в новом чате (клиент получает их при инициализации). Кэш MCP-обработчика
    (`globalForMcp.__hubMcp`) должен сбрасываться при смене языка, как при смене «Свой initialize».
  - Рядом с переключателем — предупреждение: скрипты, которые через `hub.tool` разбирают текст ответов, после смены языка могут сломаться;
    в новом чате описания инструментов обновятся.
- **Скриншоты и демо — только английские**, один набор на оба README. Демо-данные (`scripts/demo/seed.mts`: документы, торренты, скрипты, журнал)
  переводятся на английский, демо запускается с языком `en`. `pnpm screenshots` и `pnpm demo` пересобирают `docs/screenshots/*.png`,
  `social-preview.png` и статическое демо.

## Не цели

- Другие языки сверх en/ru. Механизм не должен им мешать, но третий язык сейчас не нужен.
- Перевод того, что написал пользователь: правила разметки Paperless/Papra, свои инструкции коннекторов («Дополнить»/«Заменить»), текст «Свой initialize»,
  код и описания скриптов и `my_*`, заметки, имена тегов.
- Перевод уже записанного: журнал вызовов, история запусков скриптов, сообщения в базе остаются на языке, на котором были записаны.
- Отдельные русские скриншоты.
- Выбор языка по браузеру (`Accept-Language`).

## Анти-цели (провал, даже если работает)

- Обновление меняет настройки, ключи, имена инструментов, id (язык по умолчанию становится английским — это ожидаемо, см. «Без миграции»).
- Смешанный язык: английская админка с русскими ошибками полей, русскими датами или русскими ответами инструментов
  (кроме пользовательских текстов из «Не цели»).
- Меняются имена инструментов, параметров, полей конфигурации или ключи в базе — это ломает чаты, скрипты и сохранённые настройки.
- Английские тексты для модели заметно длиннее русских: важно для лимита 512 символов у ChatGPT (видно в «Диагностике»).
- Утечка в тексты того, что сейчас скрыто (префикс, секреты) — перевод не должен трогать эту логику.

## Ограничения

- Стек проекта не меняется: Next.js 15 App Router, серверные компоненты. Язык читается из `setting` (SQLite, синхронно) на сервере в момент запроса.
- MCP-сервер stateless: инструменты регистрируются на каждый запрос в `initializeServer`, так что описания можно брать на текущем языке.
- Строки остаются рядом с кодом, который их использует (коннектор = папка), чтобы новый коннектор приносил оба языка с собой.
- Английский текст для модели — такой же короткий и читаемый, как русский: ответы инструментов читают на телефоне.
- Документация: EN-файлы должны называть элементы интерфейса английскими подписями (сейчас там «**Коннекторы** (Connectors)»),
  RU-файлы — русскими. Правило в `CLAUDE.md` «Тексты интерфейса на русском» меняется на «на двух языках, en и ru»,
  плюс описание механизма перевода. Обе версии документации (`*.md` и `*.ru.md`) обновляются.
- `pnpm lint && pnpm typecheck && pnpm test` проходят; существующие тесты, проверяющие русские тексты, остаются рабочими (например, тесты по умолчанию
  на `ru`), плюс тесты на английский и на смену языка.

## Решено мной (можно поменять)

- **Механизм:** свой маленький модуль без библиотеки i18n: текущий язык `getLang()` из `setting`, функции для множественного числа и дат на обоих языках.
  Библиотека вроде next-intl здесь лишняя: язык один на весь хаб и известен на сервере.
- **В коде — английский** (решение пользователя): английский текст в коде служит ключом, русский — в каталоге `ru.ts` рядом с кодом. Код читается
  англоязычными контрибьюторами без каталогов.
- **Предупреждение про скрипты** рядом с переключателем, без автоматических проверок скриптов.

- **Русские тексты не меняются ни на байт:** русская строка из кода переносится в каталог `ru.ts` копированием, без перепечатывания и правок.
  Существующие русские тесты — страховочная сеть и не правятся (кроме импорта/настройки языка). Так обновление не ломает скрипты, которые разбирают русские ответы `hub.tool`.
- **Аддон mitmproxy** (`addons/mitmproxy/hub_mocks.py`) тоже переводится: хаб кладёт язык в опцию `hub_mocks` (`{allowed, rules, lang}`),
  аддон выбирает тексты по ней, а без поля (старый хаб) говорит по-русски. Старый аддон с новым хабом просто останется русским — это допустимо,
  в документации сказать, что аддон надо обновить. Метка `mock:<id> (json пропущен)` в комментариях потоков — часть протокола: не переводится и не меняется,
  хаб показывает её смысл на выбранном языке.

- **Субтитры YouTube** — вне этой работы: встроенный `browser_youtube_transcript` убран из коннектора camofox по решению пользователя,
  субтитры делаются своим инструментом `my_*` в «Скриптах». Языковых умолчаний для них в коде нет.

- **Озвучка в поиске торрентов** (решение пользователя): в настройках коннектора Jackett — текстовое поле «Предпочитаемый язык озвучки» (код языка).
  - По умолчанию `en`, в том числе у существующих установок после обновления: пользователь ставит `ru` сам.
  - `en` — английская озвучка обычна для трекеров, поэтому приоритета нет: сортировка только по сидам.
  - Сейчас хаб умеет распознавать только русскую озвучку (`lib/connectors/jackett/parse.ts`, `hasRussianAudio`). Мой выбор: добавить распознавание
    по типичным меткам релизов ещё для `uk`, `de`, `fr`, `es`, `it`, `pl`; другой код поле не примет (ошибка формы со списком доступных).
  - Параметр `language` у `search_torrents` остаётся с тем же именем: принимает код языка или `any`, по умолчанию — значение из настройки.
    Значение `ru` работает как раньше, чтобы не ломать существующие чаты и скрипты.
- **Сортировка и сравнение строк** (мой выбор): порядок имён в `files_list` (`localeCompare(…, 'ru')`) и сравнение имён тегов Paperless
  без учёта регистра (`toLocaleLowerCase('ru')`) берут локаль из языка хаба. Отдельной настройки нет.

## Оставлено исполнителю

- Точный API модуля перевода и как типизировать пары строк (чтобы нельзя было забыть один язык).
- Как прокинуть язык в клиентские компоненты (форма коннектора, переключатели).
- Порядок работы по модулям и как разбить на коммиты.
- Английские формулировки — по смыслу русских, коротко; термины сервисов (torrent, seed, tag) — как в их собственных интерфейсах.
- Как держать тесты: язык по умолчанию в тестах, какие тесты дублировать на английском.
